# Cleanup (0.6.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a person pick items in the treemap and free space with one click (Move to Trash, Delete permanently for safe items, Remove Download for iCloud copies), with Claude suggesting candidates and explaining why.

**Architecture:** A read-only `signals` module turns a finished scan into tiered candidates with reasons. A `cleanup` service owns approval: `preview` revalidates the exact items and mints a one-time token; `execute` re-checks and acts through an injectable `Executor` (real macOS implementation in `macos.py`, fake in tests). The plugin exposes one model-visible read-only tool and three app-only tools; the inline MCP Apps view and the local browser view both drive the same service.

**Tech Stack:** Python 3.9+ standard library only (`ctypes` for Foundation calls), vanilla JS/CSS in the bundled views, `unittest`.

**Spec:** `docs/superpowers/specs/2026-10-21-cleanup-design.md` (read it first; its "Clarifications after builder review" section is binding).

All paths below are relative to the repository root. `PKG` = `plugins/storage-assistant/storage_assistant`.

## Global Constraints

- Zero third-party dependencies; must run on `/usr/bin/python3` 3.9.
- macOS only. `/usr/bin/trash` exists on macOS 15+; fall back to `NSFileManager trashItemAtURL:resultingItemURL:error:` via `ctypes`.
- Automated tests use disposable synthetic fixtures only; they never touch the real Trash, iCloud or user folders. Real-system checks are opt-in (`STORAGE_REAL_MACOS_TESTS=1`) or manual.
- No content reads unless an opt-in is on: `gitHealth` (git status) and `exactDuplicates` (hashing). Opt-ins can only be switched on from a view, never by the model.
- Thresholds: recently changed = 7 days (never suggested); active project = any file outside its rebuildable folders changed within 30 days; "untouched" = 365+ days; Spotlight lookups for at most the 300 largest candidates; token expiry 300 s; at most 500 items per action; permanent deletion of a folder walks at most 250,000 descendants (more → refuse that item).
- Tier names (exact): "Safe to clear", "Worth a glance", "Your call". Internal codes: `safe`, `glance`, `your_call`.
- Button and confirmation copy (exact): `Move N items to Trash`, `Delete permanently, free X now`, `Remove N downloads (keep in iCloud)`, `Delete N items permanently? This can't be undone.`, `Open Trash`, `Review…`.
- Release version `0.6.0` in `plugins/storage-assistant/plugin.json`, `plugins/storage-assistant/.claude-plugin/plugin.json`, `packaging/mcpb/manifest.json`, `PKG/__init__.py`.

## Review Focus

1. A selection containing a folder and something inside it → act once on the folder; the child is reported as "included in its folder", not double-counted in "frees X". (Task 6)
2. The person rescans, or the scan is replaced, while a review is open → execute refuses with "This folder was rescanned. Review again." and nothing is touched. (Task 6)
3. Double-click on the action button → the second execute is refused (token already used); the receipt from the first stands. (Task 6)
4. macOS denies access to one selected item → that item fails with "macOS denied access", the others still complete, and nothing falls back to permanent deletion. (Task 6)
5. A selected file was replaced by a symlink (or moved out of the folder) after review → skipped with "Changed since you reviewed it"; the link target is untouched. (Task 6)
